### 안녕하세요, 김현민(Jayden)입니다

궁금하면 뜯어보고, 불편하면 만들고, 되는지 모르겠으면 일단 해 봅니다.

일은 FDE(Forward Deployed Engineer)로 하고 있어요. 고객사 안에 들어가서, 덩어리로 받은 일을 에이전트가 맡을 수 있는 크기까지 쪼개는 일이죠. 지금은 [NxtCloud](https://nxtcloud.kr)에서 FDE 팀을 꾸리고 있습니다.

#### 좋아하는 것

- **원리 뜯어보기.** 쓰는 법보다 왜 그렇게 동작하는지가 더 궁금한 편입니다. 막히면 에러 메시지에서 멈추지 않고 소스까지 따라가 보고, 잘 돌아가는 것도 왜 돌아가는지 한 번은 들여다봐요. 잘 돌아가는 게 제일 수상하거든요.
- **불편을 도구로 바꾸기.** 하루에 몇 번씩 걸리는 작은 불편은 참기보다 고치는 쪽이에요. 몇 초짜리 일이라도 매일 반복되면 결국에는 하나 만들게 되더라고요. 만드는 데는 몇 시간씩 걸리지만요.
- **직접 재 보는 것.** 리더보드에 숫자가 있어도 제 맥에서 다시 돌려 봐야 믿습니다. 공식 문서에 리눅스만 된다고 써 있으면 맥에서 한번 붙여 보고요. 제 맥이 고생이 많습니다.
- **말로 생각하기.** 생각은 말하면서 정리되는 편이에요. 혼자 한참 떠들어 녹음해 두고, 받아 적은 걸 다듬어서 글로 만듭니다. 받아 적고 보면 "결국에는"이 유난히 많아요.
- **공부한 걸 남기기.** 배운 건 남이 읽을 수 있게 정리해 둬야 제 것이 되는 것 같아요. 그래서 공부하다 보면 노트가 교재가 되고, 써 본 도구는 실습 자료로 남습니다.
- **좋은 질문.** 정답을 묻는 질문보다 뭘 생각해야 하는지 되묻게 만드는 질문이 좋습니다. 그런 질문은 팀원한테서 오든 고객한테서 오든 한참 붙잡고 있게 됩니다.

#### 일할 때는

- 프롬프트보다 쪼개기에 시간을 더 씁니다. 정해진 규칙으로 끝나는 건 코드로 돌리고, 판단이 필요한 곳에만 AI를 넣어요.
- AI가 만든 결과는 같은 AI한테 채점시키지 않습니다. 짜는 모델과 보는 모델을 따로 둬요. 자기 숙제를 자기가 채점하면 다 맞았다고 하니까요.
- 규칙은 문서보다 테스트로 겁니다. 에이전트는 세션마다 처음 보는 사람처럼 들어오거든요.
- 생각은 AI한테 넘기지 않으려고 합니다. 문제는 제가 정의하고, AI한테는 평가를 받아요.
- 혼자 일하는 게 편한 사람인데, 해 보니 큰 일은 서너 명이 나눠 맡아야 되더라고요. 고치고 있습니다.

#### 요즘 붙잡고 있는 질문

- AI를 쓴 사람이 진짜 생각을 했는지는 어떻게 알아볼 수 있을까
- 안에서는 잘게 쪼개서 처리한 걸, 쓰는 사람한테는 어떻게 단순하게 보여 줄까
- 내 맥에서 도는 모델은 언제쯤 진짜 일에 붙을 수 있을까
